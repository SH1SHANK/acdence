Trekking Management Application - V2
Overview
Adventure organizations require efficient systems to manage trekking activities involving trek organizers, staff, and
participants. The Trekking Management Application (TMA) is a web application that allows Admin, Trek Staff, and
Users (Trekkers) to interact with the system according to their roles.
Frameworks to be Used
  Flask for API
  VueJS for UI
  VueJS Advanced with CLI, only if required
  Jinja2 templates only for the entry point when using CDN; not for UI
  Bootstrap for HTML generation and styling; no other CSS framework
  SQLite for the database; no other database
  Redis for caching
  Redis and Celery for batch jobs
 All demos should be possible on the local machine. Other frameworks/libraries are not allowed apart from those
specified. The database must be created programmatically through table creation or model code; manual database
creation using tools such as DB Browser for SQLite is not allowed.
Roles & Functionalities
Admin
  Create, update and remove trekking routes
  Add and manage trek staff
  Assign staff to treks
  View and manage all users, staff, and treks
  Search users, staff, or treks
  Deactivate or blacklist users or staff
  View reports and trekking statistics
 
Trek Staff
  Log in only after being created by Admin
  View treks assigned by Admin
  Manage available slots
  Manage trek status: Open / Closed
  View registered users for assigned treks
  Update trek completion status
 
User (Trekker)
  Register, log in, and update profile
  View approved/open treks
  Search and filter treks by difficulty, location, and duration

Key Terminologies
Admin
A user with the highest level of access who manages the entire trekking system.
Trek Staff
A staff member responsible for managing and coordinating assigned treks.
User (Trekker)
A participant who books and participates in trekking activities.

Booking

Core Features
Authentication
  Login/register for Users (Trekkers)
  Login only for Admin and Trek Staff; no registration
  Exactly one Admin must exist and must be created programmatically
  Role-based authentication and access control using Flask security, session/token authentication, or JWT
  Unified user model differentiating user roles
 
Admin Functionalities
  Dashboard showing total treks, total users/staff, and total bookings
  Admin is pre-existing and created programmatically after database creation; no Admin registration
  Create and manage trek routes
  Add new trek staff
  Assign staff to treks
  View all bookings
  Search users, staff, and treks
  Deactivate or blacklist users/staff
 
Trek Staff Functionalities
  Dashboard displaying assigned treks and number of registered users per trek
  Update trek slots and status
  View and manage participant list
  Mark trek as started/completed
 
User Functionalities
  Self-register and log in

Backend Jobs
Scheduled Job — Daily Reminders
  Send daily reminders to users about upcoming treks
  Include trek start date, instructions, and related information
  Delivery can use email, SMS, or Google Chat webhooks
  Runs daily at a chosen time
 
Scheduled Job — Monthly Activity Report
  Generate a monthly trekking activity report for Admin
  Include number of treks conducted, number of users participated, and popular treks
  Generate on the first day of every month
  Send to Admin via email as HTML or PDF
 
User-Triggered Async Job — Export Booking History as CSV
  Users can export their trekking history
  CSV fields: User ID, Trek Name, Location, Booking Status, and Dates
  Triggered from the user dashboard
  Export should run as a batch job and send an alert once completed
 
Performance and Caching
  Use Redis caching for frequently accessed treks
  Implement cache expiry
  Optimize API response times
 
Other Core Functionalities
  Prevent overbooking beyond available slots
  Ensure only assigned staff can manage a trek
  Allow booking only when trek status is Open
  Prevent duplicate bookings for the same trek
  Maintain complete trekking history per user
  Allow searching and filtering of treks
  Allow Admin to view all historical trekking data
 
Recommended / Optional Functionalities
  Well-designed PDF reports for monthly activity reports
  Charts for analytics, such as popular treks and user participation, using ChartJS
  Single responsive UI for mobile and desktop
